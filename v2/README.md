# V2 本地自动采集工作台

关键词 → 搜索结果发现 → 本地任务队列 → 自动逐帖打开与滚动 → 去重保存 → CSV/JSON。

## 启动

需要 Node.js 22或更新版本，以及电脑端Chrome。无需服务器或API Key。

- Windows：解压仓库，双击根目录 `启动V2.cmd`，首次自动安装依赖，服务启动后打开本地工作台。
- macOS / Linux：在项目目录执行 `sh 启动V2.sh`。
- 或在终端执行 `npm ci`、`npm start`，浏览器打开 `http://127.0.0.1:8765`。

默认用系统Chrome启动独立采集窗口。只有Edge时，Windows终端先运行 `set COLLECTOR_BROWSER=msedge`，再 `npm start`。macOS/Linux可运行 `COLLECTOR_BROWSER=msedge npm start`。

也可先执行 `npx playwright install chromium`，再把 `COLLECTOR_BROWSER` 设为 `chromium`。不使用日常浏览器的主用户目录，不读取现有浏览器的Cookie。首次需要在**采集专用窗口**正常登录；以后复用该窗口自己的本地登录状态。

## 操作

1. 建议先选择“合成演示”，输入任意关键词，设置2个帖子、每帖10条，确认进度和导出流程。演示数据正文带 `[合成演示]`，不会访问平台。
2. 真实任务先选平台，点击“打开所选平台登录窗口”，正常登录；不要将密码、验证码或Cookie发给他人。
3. 回工作台选择“真实采集”，输入1–10个搜索关键词，每行一个或逗号分隔。
4. 设置整项任务的帖子总数（1–50）、每帖保存评论上限（1–500）、评论过滤关键词和操作间隔（3–30秒）。多个搜索关键词共用帖子总数上限，前面的关键词可能先占满。
5. 创建任务，程序自动打开搜索页面，从可见链接发现帖子并去重，然后依次打开帖子、读取已加载评论并滚动。搜索每词最多12轮滚动，连续3轮无新帖子停止该词；评论每帖每次执行最多80轮，达到上限或连续5轮无新增时结束。
6. 查看帖子完成数、评论数、失败记录和日志。可暂停、取消、继续、重试失败帖子，或随时导出当前已保存的评论。

任务串行执行；同一时间只用一个采集窗口。不要在自动采集期间手动切换该窗口页面。要登录或处理验证，先暂停；任务进入“等待登录/验证”后会暂停整个队列，后续任务不会抢走验证窗口。手动处理后点继续，不会自动解决验证或切换网络。

## 断点与限制

- 每轮读取后原子保存到 `private/v2/tasks.json`；服务重启时未结束任务转为“已暂停”，点击继续。
- 已完成帖子会跳过；未完成帖子重新打开，从顶部重新滚动并去重。保存读取轮数以避免过早判定无新增，但不保存精确滚动位置；单次80轮上限内仍可能未回到之前的位置。
- 正常退出会先保存进度。强制断电可能丢失最后一次未完成保存，已落盘的检查点保留。
- 单帖失败记录保留，继续处理后续帖子。任务“已结束”可能包含失败帖子，请看失败数量。无匹配评论也记为待检查，并不推断平台没有评论。
- 页面URL、签名链接、原始评论及浏览器登录状态仅保存在本机 `private/v2/`，默认被Git忽略；不要公开上传这个目录。导出中的来源URL去掉签名/跟踪参数，可能无法直接重开。
- V1扩展与V2使用独立存储，不自动迁移V1数据。
- 目前只扫描当前搜索页可见链接并滚动，不点搜索“下一页”、不逆向接口，不保证发现所有结果。评论楼中楼需平台正常展开；尚不自动展开全部回复。
- 小红书、抖音搜索卡片可能依赖点击/动态结构，若没有可识别的帖子链接，任务会明确失败；目前未完成三个平台真实自动搜索整流程验证。高级选择器可调整**评论字段**，不能调整搜索链接发现或登录检测。
- 自定义规则使用CSS，不执行用户输入代码。平台可能变更DOM或新增验证，仍为实验版。

## 本地数据与服务

界面只绑定 `127.0.0.1`，要求本地Host/Origin及随机请求凭证；不提供远程托管。数据目录不会作为HTTP静态资源暴露。请勿把此服务通过隧道或端口映射公开。

环境变量：`PORT`（默认8765）、`COLLECTOR_DATA_DIR`（默认项目 `private/v2`）、`COLLECTOR_BROWSER`（chrome/msedge/chromium）。程序运行时需要保持电脑唤醒、网络可用和终端未关闭，不是云端定时服务。

